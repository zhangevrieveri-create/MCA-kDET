# 快速版结果与理论、方法的一致性分析

2026-10-22。依据：快速版 E1–E7（`results_v2_quick/`）、libsize（D 原假设 1000 次）、草稿第 2–3 节。定量检查的脚本是 `analysis_theory_checks.R`，输出在 `results_v2_quick/theory_checks.txt`。

**总的结论：** 结果与第 3 节的理论一致，没有发现与定理 1、定理 2、推论 1、注 10、注 11、命题 1–2 相矛盾的地方。实现上发现 glmnet 在弱惩罚下常常不收敛（见第 2 节，10-22 已更正）：它不影响方法的正确性和水平，只是让 E1 很慢；已把 `maxit` 从 1e5 降到 1e4，并开始记录不收敛的次数。

## 1 结果与理论逐条对照

### 1.1 定理 1（有限样本水平）：一致

定理 1 给出 Pr(p ≤ α) ≤ ⌊α(B+1)⌋/(B+1) = 10/201 = 0.0498。把快速版里所有原假设的重复合并起来（E1 的 4800 次、E4 的 200 次、E5 的 1200 次）：

| 统计量 | 重复次数 | 拒绝率 | 95% 置信区间 | 与上界 0.0498 是否一致 |
|---|---|---|---|---|
| **MCA（库）** | 6200 | **0.0505** | [0.0452, 0.0562] | 一致 |
| 单学习器 l1 / quad / knn / rf | 6200 | 0.043 / 0.051 / 0.046 / 0.047 | 都包含 ≤ 0.0498 | 一致 |
| 双侧 / 求和 / 组合 | 6200 | 0.049 / 0.046 / 0.047 | | 一致 |
| 两两比较 | 3600 | 0.045 | [0.039, 0.053] | 一致 |
| 共享网络 / 多类准确率 | 5000 | 0.044 / 0.039 | | 一致 |
| 多次拆分：2 倍中位数 / 2 倍均值 | 1200 | 0.001 / 0.000 | | 一致（极度保守） |

此外：
- E1 中 MCA 在 α = 0.01 / 0.05 / 0.10 时的拒绝率分别为 0.008 / 0.049 / 0.095，p 值的 KS 均匀性检验 p = 0.46。
- 单独加跑的 libsize（D 原假设，1000 次）为 0.043。
- 定理 1 说明它对"成对、双侧、共享、求和型变体和多次拆分合并"同样成立，这些都得到了验证。
- 不等样本量（注 8）、k = 10、d = 300 下也都成立。

### 1.2 注 12（原假设下 T 近似标准正态）：一致；l1 因并列而偏保守

| 学习器 | T 的均值 | T 的标准差 | P(T = 0) | P(T > 1.645) |
|---|---|---|---|---|
| quad | +0.012 | 0.976 | 0.057 | 0.047 |
| knn | −0.010 | 0.965 | 0 | 0.045 |
| rf | −0.001 | 0.980 | 0 | 0.046 |
| l1 | −0.001 | **0.758** | **0.404** | 0.028 |

quad、knn、rf 的 T 非常接近 N(0, 1)。l1 有 40% 的情况 T 恰好为 0：原假设下 CV 常常选中最强的惩罚（"并列取最强惩罚"），所有系数为 0，分数全部相同，AUC 恰好为 1/2。这正是定理 1 后面所说的"统计量可能有并列，所以检验一般偏保守"，因此 l1 单独作库时拒绝率略低（0.043）。这和理论一致，不是问题。

### 1.3 定理 2 与推论 1（功效由学到的信号决定）：定性上一致；定理 2 的界非常保守

把 k = 3 的备择格（E2、E3、E6，共 3000 次）按"四个学习器中偏离总体测试 AUC 的最大值"分组：

| 最好学习器的 AUC | 重复次数 | MCA 功效 | ρ 的中位数 | 定理 2 给出的功效下界 |
|---|---|---|---|---|
| < 0.52 | 424 | 0.035 | 0.0 | 0 |
| 0.52–0.54 | 381 | 0.026 | 0.1 | 0 |
| 0.54–0.56 | 412 | 0.041 | 0.2 | 0 |
| 0.56–0.58 | 374 | **0.342** | 0.5 | 0 |
| 0.58–0.60 | 331 | **0.997** | 0.8 | 0 |
| ≥ 0.60 | 1078 | **1.000** | 1.2–14 | 0（直到 AUC 约 0.9 才不为 0） |

- **定性上与定理 2 和推论 1 完全一致：** 功效几乎完全由学到的信号 δ̂ 决定，呈阶跃状。AUC 低于 0.56 时检验基本不拒绝，高于 0.58 时几乎必然拒绝。0.58 约相当于原假设标准差的 2.8 倍（AUC 的原假设标准差为 0.029），正好对应 12 个标准化统计量（k = 3 × q = 4）取最大时的临界值。
- **定量上，定理 2 的界非常保守：** 在这些格里它给出的功效下界全是 0，要到 AUC 约 0.9（ρ > 16）才开始起作用。这正是注 12 说的"Hoeffding 用的是秩的取值范围而不是方差，所以第二项偏保守"。建议正文在注 12 里加一句实测的说法，例如："实际的拒绝门槛约为 1/2 + z_{1−α/(kq)} × 原假设标准差；我们的模拟中约为 AUC 0.58"。见第 3 节。

### 1.4 注 11（维数只通过学到的信号起作用）：一致

E6 中模型 A，按同样的 AUC 分组、按维数分列（格内数字是 MCA 功效，括号里是重复次数）：

| AUC 分组 | d = 50 | d = 100 | d = 300 | d = 1000 |
|---|---|---|---|---|
| < 0.55 | 0.00 (8) | 0.00 (5) | 0.07 (28) | 0.02 (46) |
| 0.55–0.57 | 0.00 (14) | 0.06 (17) | 0.09 (23) | 0.04 (24) |
| 0.57–0.59 | 0.89 (19) | 0.75 (24) | 0.86 (28) | 0.70 (23) |
| ≥ 0.59 | 1.00 (59) | 1.00 (54) | 1.00 (21) | 1.00 (7) |

**在 AUC 相同的条件下，功效与维数无关**（每一行在 d = 50 到 1000 之间只有噪声级别的差异）。维数升高只是让 AUC 落在低分组的重复变多了（看括号里的次数）。这正是注 11 的结论："维数只通过学到的信号 δ̂ 影响功效，(3.2) 和推论 1 本身不含 d"。

### 1.5 注 10（库的代价，量级为 log(kq)）：一致，而且可以定量解释

E2 中 A β = 0.8 时，l1 单独 0.80，库 0.65。用临界值的近似来解释：l1 单独时要对 k = 3 个统计量取最大，临界值约为 z_{1−0.05/3} = 2.13 个原假设标准差；库要对 12 个取最大，临界值约为 z_{1−0.05/12} = 2.64。按 l1 实测的 AUC 分布：

- P(l1 的 AUC > 1/2 + 2.13 个标准差) = **0.80**，实测 l1 单独为 **0.80**；
- P(l1 的 AUC > 1/2 + 2.64 个标准差) = **0.61**，实测库为 **0.65**。

也就是说，库的代价几乎完全来自取最大的统计量从 k 个增加到 kq 个，临界值随之抬高，这与注 10 的 log(kq) 机制吻合。库里其他学习器偶尔贡献一点额外的信号，所以实测比近似值略高（0.65 对 0.61）。

## 2 实现与方法（算法 1、假设 2）的一致性

| 要求 | 实现 | 结论 |
|---|---|---|
| 每个总体内随机拆分，τ 事先固定 | `split_data`：拆分来自随机数流，与观测值无关 | 一致 |
| 学习器只用 D_fit 和独立的随机性；所有预处理、调参、早停都只用 D_fit | 标准化用拟合数据的均值和标准差；quad 的交叉项筛选、L1/quad/kNN 的 CV 都只在 D_fit 内进行；rf 的种子从随机数流抽取；对测试数据只做预测，不消耗随机数 | 一致 |
| 所有统计量共用一组置换（第 6 步），p 值按 (2.8) 计算 | `classifier_tests` 只生成一次 `Lall`，供所有学习器、变体和库组合共用；`pval_perm` 使用"≥" | 一致 |
| 库、B、τ 事先固定 | 库在 E1–E7 之前就由试点定下（试点用的是不同的种子），B = 200，τ = 0.5 | 一致；正文需要说明库是由试点选出的（见第 3 节） |
| 置换与测试数据独立 | 置换在拟合之后从同一随机数流生成；流的状态只取决于种子和 D_fit（学习器消耗多少随机数只和拟合数据有关），与 D_test 无关 | 一致 |
| L1 学习器"在选中的 C 下拟合" | **不完全一致**，见下 | 需要修复 |

**发现的问题：glmnet 在弱惩罚下不收敛（2026-10-22 更正后的版本）。**

这一段原来的说法有误，已更正。原来说"不收敛时静默输出全零系数"，那是诊断脚本 `tests/diag_glmnet.R` 每一档 C 单独冷启动拟合时才出现的现象，实际代码里不会发生。

实际的 `l1_fit_score`（l1 和 quad 共用）是从最强的惩罚开始、热启动地一次拟合整条 C 路径。某一档不收敛时，glmnet 只返回之前已经收敛的那几档，并发出警告（原来被 `suppressWarnings` 吞掉了）。现有代码的处理是：CV 中缺失的档记为 NA，不参与选择；最终拟合时使用路径上最后一个收敛的解，相当于退回到惩罚更强的那一档。所以：

- **方法的正确性不受影响**：仍然是只依赖 D_fit 的学习器，定理 1 成立；也不会输出全零的常数分数。
- **问题只在耗时**：每次不收敛都要先跑满 `maxit = 1e5` 次迭代。`tests/diag_l1_path.R` 在 E1 中 A、k = 10、d = 300 的第 1 次重复里测到，l1 在 10 个总体上**每个**都遇到 1–3 次不收敛，每个总体耗时 10–30 秒（单进程），与不收敛次数成正比。在 D、k = 10、d = 100 中，quad 只在 1 个总体上不收敛 1 次，这一个总体就花了 41 秒，其余都不到 2 秒。30 个 worker 并行时这些耗时会成倍放大，这就是 E1 用了 9.3 小时的原因。
- 原假设下有不少总体选中最强惩罚、分数全部相同，这是 CV 的正常结果（并列时取最强惩罚），和不收敛无关。
- 另外发现一个小问题：退回发生时，`info` 里记录的 C 仍是 CV 选中的那一档，而不是实际用到的那一档。这只影响诊断列 `l1_log10C` / `quad_log10C`，不影响 p 值。

**改法（2026-10-22 已改，`R/learners.R`；改之前的代码备份在 `archive/code_v2_20261022/`）：**
1. glmnet 的 `maxit` 从 1e5 降到 **1e4**（常量 `L1_MAXIT`），每次不收敛的耗时降为原来的约十分之一。
2. 统计不收敛的次数，记入 `info`，输出为诊断列 `l1_nonconv`、`quad_nonconv`。其他警告照旧不显示。
3. `info` 里的 C 改为实际用到的 C。
4. 其余都不变：C 网格、CV 规则、"并列取最强惩罚"、退回方式。

唯一可能改变结果的情形是：某个拟合原来在 1 万到 10 万次迭代之间收敛，现在会被当作不收敛、退回到更强的惩罚。下面验证计划的第 3、4 步用来量化这种情况发生得有多频繁。

**验证计划（每一步跑之前都会先请用户确认参数）：**
1. 兼容性验证（smoke，lib = "l1,nn"）：p 值应当逐位不变；
2. 单元测试第 1、3 部分；
3. 用 `tests/diag_l1_path.R` 重跑两格慢格：看耗时下降了多少，以及选中的 C 和非零系数个数和改之前是否相同；
4. E1 中 A、k = 10、d = 300 和 D、k = 10、d = 100 各补跑第 1–20 次，结果写到单独的目录，与快速版相同重复的 p 值逐一对比。

**验证结果（2026-10-22，4 步全部通过）：**

| 步骤 | 结果 |
|---|---|
| 1. 兼容性验证 | smoke 的 16 个 p 值列逐位不变 |
| 2. 单元测试第 1、3 部分 | 通过，数字与修复前完全相同；第 3 部分里 quad 有不收敛，但结果不变 |
| 3. 慢格诊断（单进程，第 1 次重复） | A、k = 10、d = 300 的 l1：10 个总体合计从 206.6 秒降到 **23.7 秒**，不收敛次数（21 次）、选中的 C、非零系数个数**全部相同**；D 的 quad：第 4 个总体从 41.3 秒降到 4.7 秒，其余不变 |
| 4. E1 两格慢格各补跑第 1–20 次（`results_check_glmnet/`） | 40 次重复的 **16 个 p 值列全部逐位相同**；每次重复合计从 1209 秒降到 328 秒（A）、从 638 秒降到 363 秒（D） |

结论：修复只改变速度，不改变结果，所以已有的快速版结果可以直接沿用。按新的速度粗估，精确版 E1 约从 25 小时降到 14 小时，精确版合计约从 31 小时降到 20 小时（E1 以外的实验几乎不受影响）。
